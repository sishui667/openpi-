## 1. 核心关系

成员 A 与成员 B 是上下游协作关系，不是两套相互独立或互相替代的抓取方案。

- **成员 A 负责“人想怎样操作”**：从人体视频或摄像头中提取手臂、手腕和手指动作，将其转换为机器人可理解的示范动作。
- **成员 B 负责“机器人应在什么位置执行，并保证动作在仿真中真实完成”**：通过胸部相机寻找方块、通过腕部相机精定位，再完成 IK、轨迹生成、限速、平滑和 MuJoCo 执行。

完整链路为：

```text
人体视频/实时摄像头
        ↓
成员 A：人体关键点提取、动作映射、夹爪意图
        ↓
相对末端动作 Δpose + 夹爪状态
        ↓
成员 B：胸部相机全局定位、选择机械臂
        ↓
成员 B：腕部相机精定位方块
        ↓
将 A 的相对示范轨迹锚定到当前方块位置
        ↓
视觉目标 + IK + 关节限位 + 速度平滑
        ↓
MuJoCo 真实接触、摩擦抓取与 Episode 记录
```

## 2. 两人的工作怎样连接

| 成员 A 的输出 | 成员 B 的处理 | 最终作用 |
|---|---|---|
| 人体手腕运动轨迹 | 转换为相对末端位移增量 | 决定机械臂怎样接近、抬升和移动 |
| 手指捏合距离 | 使用双阈值迟滞映射 | 控制夹爪张开、保持或闭合 |
| 动作时间戳与帧号 | 与仿真和相机帧同步 | 生成可复现的 Episode |
| 动作置信度 | 写入数据质量字段 | 供成员 C 进行异常数据筛选 |
| Pose2Arm 轨迹 | 做坐标重定位、IK、限位和限速 | 驱动 MuJoCo 执行器 |

成员 A 给出的是**示范动作的形状和意图**；成员 B 利用视觉确定方块当前在哪里，并把动作准确放到该位置。

## 3. 推荐的融合方式：物体中心坐标系下的相对动作

不能把成员 A 的关节角与成员 B 的 IK 关节角直接相加，因为两者同时控制同一机械臂，会产生跳变、超速和控制权冲突。

推荐将成员 A 的动作转换为相对末端轨迹：

```text
ΔP_A(t) = P_A(t) - P_A(0)
```

成员 B 使用胸部和腕部 RGB-D 相机得到当前方块的抓取基准位姿：

```text
T_grasp = VisualGraspPose(chest_rgbd, wrist_rgbd)
```

最终执行目标为：

```text
T_target(t) = T_grasp ⊕ ΔT_A(t)
q_target(t) = IK(T_target(t), q_previous)
```

其中：

- `T_grasp` 随方块初始位置变化；
- `ΔT_A(t)` 保留真人示范中的接近、下移、抬升和搬运动作；
- `q_previous` 用于保持 IK 解连续，避免关节解突然翻转；
- 最终关节目标仍由成员 B 的驱动层进行限位、速度限制和平滑。

这样，同一条真人示范轨迹可以迁移到桌面上的不同方块位置。

## 4. 建议成员 A 提供的统一接口

目前 Pose2Arm 数据主要包含：

```text
target_obs
joint_angles
frame_indices
fps
```

其中 `joint_angles[:, 0:7]` 是左臂，`joint_angles[:, 7:14]` 是右臂。

为了与成员 B 的视觉 IK 正式融合，建议成员 A 增加以下字段：

```json
{
  "timestamp_s": 0.05,
  "frame_id": 1,
  "delta_ee": [0.001, -0.002, 0.000, 0.0, 0.0, 0.0],
  "pinch_distance_m": 0.032,
  "gripper_state": "hold",
  "confidence": 0.96
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `delta_ee` | `[dx, dy, dz, droll, dpitch, dyaw]`，相对于示范起点的末端增量 |
| `pinch_distance_m` | 食指尖和拇指尖之间的实际距离 |
| `gripper_state` | `open`、`hold` 或 `close` |
| `confidence` | 人体关键点或手指检测置信度 |
| `timestamp_s` | 与视频、相机和仿真状态同步的时间戳 |

夹爪迟滞规则保持项目计划中的定义：

```text
D < 0.025 m       → close
D > 0.045 m       → open
0.025 ≤ D ≤ 0.045 → 保持上一状态
```

当前 Pose2Arm 输出中没有手指数据，因此这是成员 A 需要补充的关键接口。成员 B 不应长期使用“夹爪到方块距离”代替人的捏合距离，否则无法证明夹爪动作来自真人示范。

## 5. 推荐的融合状态机

```text
SEARCH
  胸部相机检测方块，确定全局位置并选择左臂或右臂
    ↓
OBSERVE
  机械臂先抬高，再移动到腕部相机观察位
    ↓
ALIGN
  腕部相机精定位，生成抓取基准 T_grasp
    ↓
DEMONSTRATE
  读取成员 A 的 ΔT_A(t)，生成 T_target(t)
    ↓
GRASP
  根据成员 A 的 pinch_distance_m 控制夹爪迟滞开闭
    ↓
LIFT_AND_MOVE
  B 持续执行 IK、限速和平滑；A 提供相对搬运动作
    ↓
RELEASE
  A 的张手动作触发释放，B 记录任务成功与否
```

控制权原则：

- A 决定动作意图、运动增量和夹爪开闭；
- B 决定视觉抓取基准、IK 解、轨迹连续性和仿真执行；
- 任意时刻只有 B 的执行器接口向 MuJoCo 写入最终关节目标；
- A 的原始关节角可作为参考或对照实验数据，不直接与 B 的 IK 关节角叠加。

## 7. 推荐对照实验

为了体现 A+B 融合的研究价值，建议设置三组实验：

### 实验 1：A 单独使用绝对动作

- 固定方块位置时回放 Pose2Arm 轨迹；
- 改变方块位置后仍回放同一轨迹；
- 记录抓取成功率、末端误差和碰撞次数。

预期：固定位置可能成功，方块位置变化后成功率明显下降。

### 实验 2：B 单独使用视觉 IK

- 随机改变方块初始位置；
- 使用胸部和腕部相机完成自主定位与抓取；
- 记录视觉误差、IK 成功率、抓取成功率和耗时。

预期：能够适应不同位置，但没有体现真人示范动作迁移。

### 实验 3：A+B 视觉重定位融合

- 使用同一条成员 A 示范轨迹；
- 方块在机械臂可达区域内随机放置；
- B 将 A 的相对动作锚定到每次视觉识别出的抓取位姿；
- 测试抓取、搬运和释放全过程。

预期：既保留真人示范动作，又能适应不同方块位置。这一组应作为最终系统的主要成果。

## 8. 验收指标

每组至少测试 20 次，并记录：

| 指标 | 目标 |
|---|---|
| 胸部 + 腕部视觉平面定位误差 | 尽量小于 5 mm |
| 末端跟踪误差 | 记录均值、P95 和最大值 |
| 方块抬升高度 | 大于 30 mm |
| 夹爪与方块中心距离 | 小于 20 mm，持续至少 0.5 s |
| 单次任务耗时 | 不超过 15 s |
| 不同初始位置抓取成功率 | A+B 高于 A 单独回放 |
| 动作平滑性 | 对比速度峰值、加速度峰值和关节抖动 |

## 9. 一句话总结

成员 A 生成“以人为来源的相对操作动作”，成员 B 利用胸部与腕部视觉确定“动作应该落在哪里”，再通过 IK 和仿真执行把这条示范轨迹迁移到任意可达的方块初始位置。A+B 的融合点应是**物体坐标系下的末端增量和夹爪意图**，而不是直接叠加两套关节角。
