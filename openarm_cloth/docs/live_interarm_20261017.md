# 摄像头实时双臂协调（2026-10-17）

## 改动范围

针对 `live_bimanual_human.py --runtime split`，不是人体视频离线 NPZ 生成器。原来左右臂分别求 IK，目标直接送入 PD；物理接触本身不是绕行规划。

新增 `realtime_bimanual_planner.py`，在 IK 与执行器之间协调两臂。使用机器人编码器、真实关节范围和当前模型碰撞几何；没有读取方块坐标、未来人体帧或预录绕行轨迹。识别、握拳判定和腕部映射本轮没有修改。

## 执行过程

1. 正常无碰撞时沿用原关节速度上限跟随，不给所有人体动作额外增加平滑延迟。
2. 按约三个控制步的关节目标检查前方路径。预计有碰撞时，在独立线程搜索双臂联合绕行；控制线程不等待整次搜索完成，仍尝试安全的前进步。
3. 找到路径后固定执行该条路径，限制每步关节运动，并对安全的转角做平滑；不会每帧重新选择上/下、左/右方向。
4. 人体目标明显变化时请求重规划；旧目标和起点已经不匹配的路线不能突然执行。绕行结束后接回当前示范目标。
5. 若已经接触，普通“从起点到终点都必须安全”的检查必然拒绝任何动作。此时只允许小幅、距离单调改善的脱离动作，不继续把旧目标顶向另一臂。

规划器复用了成员 A 的 RRT-Connect 实现，但关节上下限、夹爪几何和碰撞查询使用成员 B 当前仿真模型，不能直接沿用 A 的夹爪角度布局。查询用独立模型和独立 `MjData`；扩展的查询余量不作用于真实动力学模型。默认间距阈值 8 mm，边检查按关节增量采样，**不是数学上的连续无碰撞保证**。

也检查臂与躯干/同臂非邻接部分的接触，避免只躲开另一只手却把手臂绕进机身。保持原模型的相邻连杆过滤；同一空夹爪的两指自然闭合不作为绕行障碍。

## 状态显示与记录

实时界面新增 `ARMS` 状态、路线编号和控制侧检查耗时；每轮 NPZ 增加 `avoidance_mode`、`avoidance_clearance_m`、`avoidance_control_ms`、`avoidance_route_id`。线程搜索失败时显示原因，而不是把窗口无响应与无可行路径混为一谈。

| 状态 | 含义 |
| --- | --- |
| tracking | 正常跟随 |
| planning / replanning | 后台正在搜索或更新路径 |
| detour | 执行已检查的绕行路径 |
| separating_contact | 尝试逐步脱离已有接触 |
| infeasible_reference | 原目标本身碰撞，已到达附近可行姿态 |
| contact_needs_reset | 没有找到局部脱离步，不能继续强推 |
| input_missing / paused | 人体姿态缺失或用户暂停 |

## 验证与边界

独立测试覆盖：私有查询模型不改真实碰撞参数、无障碍与暂停、过期路线丢弃、规划超时、已有接触的分离、异步绕行后返回目标，以及真实 PD/重力动力学跟随。

暂存版连同原有回归共运行 99 项检查，96 项通过，3 项符号链接检查因环境创建权限不足而跳过。真人双臂交叉尚未复测，不能将单一动力学测试外推为全部工况成功率。

固定的可行终点测试中，原直线路径被阻挡，后台搜索后完成绕行。动力学回放初次验证使用原 PD/力矩限制、每周期 100 个物理步：49 个控制周期到达目标附近，记录到的双臂接触为 0，最大关节目标误差约 0.0194 rad。这只是该合成工况，不代表真人交叉动作成功率，也不是实时端到端速度证明。

简单排斥/侧向让行原型在部分换位工况仍死锁，因此未安装该原型。生产入口采用独立搜索线程方案。RRT 有时间预算和随机性，复杂窄通道仍可能找不到路线；两臂目标本身重叠或超出关节范围时，不可能既完全复制人体动作又保持无碰撞。附近可行目标搜索的最大局部关节偏差为 0.35 rad。

未关闭真实碰撞、未提高力矩、未更改冻结抓取场景。新方案仍需要真人慢速交叉、双掌靠近、交叉后分开及目标突然撤回的复测；本轮未解决之前的握拳/张掌识别问题。
