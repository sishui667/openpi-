## 识别与控制

人体模型、左手 ROI 模型、右手 ROI 模型并行处理同一个当前摄像头画面，各自拥有独立的跟踪器。ROI 框由上一帧人体位置选择，输出再与本帧人体手腕关联；漏检时限频使用双手全画面搜索。

来自重叠裁剪框的重复手腕候选先去重，再执行一对一左右手关联，同一检测不能同时驱动两个夹爪。双手交叉/互相遮挡时单目识别仍可能模糊；没有足够证据时保持缺失，不为凑齐双手而补造关键点。合成的交叉关联测试不是实际交叉遮挡场景成功率。

左右侧 IK 使用各自真实 MuJoCo 关节轴、限位和 TCP，不直接复制或反号另一臂的关节角。双侧分别保持滤波、标定、姿态缓存和握拳状态。物理控制仍为目标 20 Hz，每控制周期完整推进 100 个 0.5 ms 物理步，不靠跳过物理来提速。

## 同步性优化：控制与显示分离

2026-10-16 的 `outputs/live_bimanual/20261016_222612_088409/` 测试中，有效新人体输入的识别平均约 23.2 ms，但界面刷新平均约 96.2 ms，控制准备/物理各约 11.7/23.9 ms。旧版将这些放在同一循环，50 ms 的仿真动作间隔被拉长为约 130 ms 的现实时间，形成明显慢放。这些值只对应此轮记录，不是通用硬件性能。

当前默认 `--runtime split`：物理/IK/记录运行在独立的 20 Hz 目标线程；OpenCV 与 MuJoCo 窗口只显示最新状态。真实 `MjData` 仅由控制线程读写；渲染使用另一份 `MjData`，不把正在步进的数据交给界面并发访问。完整保留每周期 100 个物理步，并记录 `control_period_ms` / `control_compute_ms`。`display.csv` 单独记录显示开销；窗口卡顿不能再决定物理步进速度。若计算本身超过 50 ms 会如实体现，不能保证硬实时。

渲染同步使用 state-only，关闭显示阴影/反射（不改接触或重力物理）。去除关键点 One Euro 之后重复的 65 ms 方向 EMA，保留关键点滤波；双臂关节目标速度上限从 1.8 调整为 2.5 rad/s，腕部仍为 4.4 rad/s，均不超过对应模型关节速度上限。未增加电机力矩或 PD 增益。旧单臂入口仍保留其原始滤波参数。

`--runtime legacy` 可运行旧的控制/界面共循环结构，但控制算法默认参数已经更新；严格的前后对照应使用各次 manifest 的代码哈希与相同输入。摄像头到首个物理步的延迟不含物理跟踪与最终显示时间，不等于人眼看到的端到端同步误差。

## 掌心对掌心的朝向修正

原来的相对转腕标定把两只手的初始掌面都归零，会丢失双手“掌心相对”的绝对关系。当前双臂控制按实际人体左右手的解剖学符号计算掌面法向（右手与左手符号相反），分别映射到机器人手部的宽面法向 TCP +X；这不是交换左右臂，也不是将两爪固定朝内。

TWIST 模式把人掌面法向投影到小臂法平面，保留绝对朝向并控制轴向转腕，折腕关节仍保持中位。FULL 模式用掌面法向和手指纵向共同构造绝对手部目标姿态。运动受实际关节限位约束，不能保证任意掌面姿态都可达。

合成“抬臂、掌心相对”的实际模型测试中，双侧机器人宽面法向点积约 -0.999（-1 表示完全相反），两个折腕目标保持 0；重置跟踪后关系仍保留。这是合成 IK 验证，不是本次真人视觉识别准确率。数据集增加左右人体掌面法向和机器人实测掌面法向，便于离线对照。
