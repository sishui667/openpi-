# 方块坐标来源与隔离验证

适用版本：2026-10-16 打包的 `demo_grasp_viewer.py` + `visual_grasp_planner.py` 主链路。

## 当前坐标来源

1. 用户摆位或 `--cube-test-pose` 只改变仿真环境。环境初始化后，控制器不再保留摆位参数。
2. 胸部 RGB-D：红色区域检测 → 深度反投影 → 相机标定变换 → 粗定位与选臂。
3. 腕部 RGB-D：红色区域与顶面点云 → 手眼标定变换 → 精定位与朝向估计。
4. 视觉目标传入抓取候选规划器；在方块相对面方向上计算 IK 和路径。
5. 接近后再次读取摄像头进行位置修正。

腕部目标不可见或贴近图像边界时，退回胸部视觉目标。报告的 `controller_cube_pose_source` 会标记 `chest_rgbd_fallback_after_wrist_miss`，避免把单路定位宣称为双路融合。

## 仿真真值的用途

- 设置环境：初始化方块位置与朝向。
- 评估：定位误差、方块抬升、侧移、旋转、接触点、任务结果。
- 渲染：由物理场景生成摄像头 RGB-D 图像。

规划器仅复制 `openarm_` 机器人关节编码器，不读取执行环境中的方块关节位置。独立规划状态中的虚拟方块位置/朝向，由视觉估计写入后用于碰撞检查。

夹爪是否抓住的控制判断使用双指编码器与执行器受力；真实物体接触点仅用于验收。

## 固定的内容与动态计算的内容

固定：机器人几何、关节限位、相机内外参、手眼标定、已知方块尺寸、抓取阶段顺序和候选评分参数。

动态：方块视觉中心与朝向、机械臂选择、相对面选择、IK 关节目标、接近与抬升轨迹、接近后的视觉位置修正。

因此，当前实现是已知尺寸红色方块的标定视觉抓取系统，不是回放一条固定关节轨迹，也不是完全没有先验的通用物体抓取系统。

## 可重复验证

```powershell
python verify_visual_only_contract.py --report outputs/visual_only_contract.json
```
